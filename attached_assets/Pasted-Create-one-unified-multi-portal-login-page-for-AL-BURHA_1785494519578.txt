PORTAL VALIDATION

Each portal must use completely separate account validation.

Customer:
- portal value: customer
- validate only active customer accounts
- successful login redirects to Customer Dashboard
- error: “No customer account found for this mobile number.”

Admin:
- portal value: admin
- validate only active admin and super_admin accounts
- successful super_admin login redirects to Super Admin Dashboard
- successful admin login redirects to Admin Dashboard
- error: “This mobile number does not have admin access.”

Staff:
- portal value: staff
- validate only active staff accounts
- check staff role and permissions
- successful login redirects to Staff Dashboard
- error: “No active staff account found for this mobile number.”

Agent:
- portal value: agent
- validate only approved and active agent accounts
- successful login redirects to Agent Dashboard
- error: “This mobile number is not registered as an active agent.”

Branch:
- portal value: branch
- validate only active branch accounts
- successful login redirects to Branch Dashboard
- error: “No active branch account found for this mobile number.”

SECURITY AND ISOLATION

Never automatically detect another role and open the wrong dashboard.

An admin number entered under Customer Login must show the customer account error and must not open the admin dashboard.

A customer number entered under Admin Login must show the admin access error.

Apply the same strict isolation to staff, agent and branch portals.

Every OTP request must send the selected portal value to the backend.

Use one secure endpoint structure such as:

POST /api/auth/send-otp
{
  "mobile": "9893989786",
  "portal": "admin"
}

POST /api/auth/verify-otp
{
  "mobile": "9893989786",
  "otp": "123456",
  "portal": "admin"
}

The backend must verify:
- account exists in the selected portal
- account is active
- role matches selected portal
- user has permission to access that dashboard

OTP REQUIREMENTS

Use DLT SMS as the primary OTP channel.

Allow secure fallback only according to configured notification rules.

OTP expiry: 5 minutes.
Maximum verification attempts: 5.
Resend cooldown: 30 seconds.
Rate-limit OTP requests by mobile number, IP address and device.
Never return OTP, debugOtp, testOtp or code in any API response.
Never display OTP on the website.
Write all OTP attempts to audit and notification logs without storing the plain OTP.
